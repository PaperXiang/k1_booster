# 球路预测 × 定位/检测 交互排查

> 日期：2026-06-26 ｜ 范围：`k1_ball_predictor` 在 brain 内的集成、与自定位(calibrateOdom)的耦合
> 触发：核对"球路预测能否正常执行、与定位/边线检测是否冲突"
> 结论先行：**能正常执行；无硬冲突；只有一处已存在的"软交互"（定位校正会让预测球瞬间跳一下），有界、瞬态、可恢复。无需改代码。**

---

## 1. 怎么接的（执行路径）

| 环节 | 位置 | 说明 |
|---|---|---|
| 更新入口 | `Brain::updateBallPrediction()` `brain.cpp:1593` | 喂观测、取结果、写回 data |
| 调用点 | `detectProcessBalls()` 末尾 `brain.cpp:2843`（函数起 `:2754`） | **每次处理球检测**就更新一次预测器（=检测帧率，正是球滤波该有的节奏） |
| 取用 | `getBallForChase()` `brain.cpp:1637` | 仅当 `enable && use_for_chase && valid` 才返回 `predictedBall`，否则原始球 |
| 开关 | `config.yaml` `ball_prediction.enable=false`（默认） | **默认关** |

**喂的是球的 field 坐标**：`observation.position = {data->ball.posToField.x, .y}`（`brain.cpp:1603`）。
**可靠性门**：`reliable = ballDetected && ball_location_known && confidence≥阈值`（`:1605`）；不可靠时进 predictOnly(纯外推)。

## 2. 能不能正常执行 —— 能

1. **默认关时**：`updateBallPrediction()` 开头 `if (!ballPredictionEnable...) { 清空; return; }`（`:1594`）→ **完全不跑，零开销、零冲突**。
2. **打开时**：每检测帧更新；Kalman 滤波+短时预测（数学已另文 review 正确）；丢球时检测帧仍来 → `reliable=false` → predictOnly 外推，不卡死。
3. `getBallForChase` 只在 enable+use_for_chase+valid 时用预测球，否则退回原始球 → **即使预测无效也不会让追球失据**。

---

## 3. 与定位/检测的"软交互"（非硬冲突）

- 预测器在 **field 坐标**工作；自定位一旦校正（`calibrateOdom` 会**立刻把球、机器人、地标等所有对象的 field 坐标整体平移**校正量）→ 下一帧预测器看到球的 field 位置"跳了一下"。
- **本质**：球没动，是"我们对自己位置的估计"变了，连带把球的估计位置也平移了。**没有"校正时通知/重置预测器"的握手**（pre-existing，所有校正器都如此，非本轮改动引入）。
- **为什么不致命**——预测器自带异常值剔除 `max_jump_distance=1.2`（`config.yaml:43` / `brain_config.h:139`）：

| 单次定位校正量 | 哪些校正器 | 预测器反应 |
|---|---|---|
| **> 1.2m** | 点类 1M/2T/LT/2X（`max_drift≤3.5`） | 当**异常值剔除** → 短暂 predictOnly，不污染滤波 |
| **≤ 1.2m** | Line/Border（本轮已收到 `≤1.0`） | **吸收**成一次速度尖峰(瞬时≈1.0m/dt)，随后几帧平滑掉 |

两种都**瞬态、可恢复**，不崩、不阻断。

---

## 4. 本轮改动对此交互的影响（均很小）
- 重启 `SelfLocateLine`（≤1.0m、1500ms 低频、带置信度/时效/长度过滤 + validate）= 多一路**低频小幅**校正事件。
- `SelfLocateBorder` `max_drift 3.5→1.0` → 其校正现落到 1.2m 阈值**以下**，从"被剔除"变成"被吸收成速度尖峰"。
- 这些都**不接触预测器代码**，仅 field 坐标的间接耦合；**默认 prediction 关时全部不发生**。

---

## 5. 建议
- **若要测 prediction**：WebUI Prediction 卡片观察——定位 `success` 瞬间预测球/速度会**闪一下**，应很快平滑；持续乱跳才需查。
- **彻底消除（非必须、优化项）**：`calibrateOdom` 时把同一位移补偿进预测器历史，或校正瞬间跳过一帧预测更新。默认关时无意义，暂不做。

---

## 6. 一句话
球路预测**能正常执行**；与定位/检测**无硬冲突**，只有"定位校正会让预测球瞬间平移一下"的已知软交互，有界可恢复；**默认关时完全不触发**。本次无需改代码。
