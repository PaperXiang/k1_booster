## 0. 一句话总览

- **单机策略**：单台机器人在 `PLAY` 状态、给定角色（前锋 / 守门员）后，如何根据自身感知
  独立完成「找球 → 追球 → 对位 → 踢射」闭环。核心是两个决策节点 `StrikerDecide` /
  `GoalieDecide` 输出一个 `decision` 字符串，行为树按 `decision` 选动作。
- **团队策略**：多台机器人通过 UDP（100ms 单播）共享状态，在 `Brain::handleCooperation()`
  里统一算出「谁控球（lead）、谁当守门、各自站哪（按排名分工）」，把结论写进黑板供单机层读取。

> 关系链：**团队层算"我是什么角色 / 要不要控球 / 站哪" → 写黑板 → 单机层行为树读黑板 → 决定本帧动作。**

## 2. 比赛流程骨架如何分流到单机策略（`game.xml`）

`game.xml` 首行注释：**「正式比赛专用，严格执行规则，无法人工接管」**。主树是大 `Sequence`，
按 `control_state` 分三层（默认 `RunOnce` 设 `control_state=3`）：

```
control_state==1 / assist_* / go_manual   → 手动层（赛前 / 调试：SimpleChase / Kick）
control_state==2                          → 重定位层（pickup 后重新进场定位）
control_state==3 && !go_manual            → ★自动比赛层
```

自动比赛层先 `AutoGetUpAndLocate`（自动起身 + 定位），再按裁判机状态分流；其中只有
**`PLAY` 状态**进入真正的单机策略：

```
gc_is_under_penalty   → 扫场 / 找球 / 入场定位
sub_state==TIMEOUT    → 停车 + 定位
INITIAL               → 场外站好 + 定位
READY                 → GoToReadyPosition 走到场内起始位 + Locate
SET                   → 站定 + 找球 + 定位
PLAY  ┐
      ├─ player_role=='striker'     → SubTree StrikerPlay      ← 单机：前锋
      └─ player_role=='goal_keeper' → SubTree GoalKeeperPlay   ← 单机：守门
FREE_KICK(STOP/GET_READY/SET)       → GET_READY 阶段进 StrikerFreekick / GoalKeeperFreekick
END                   → 停车
```

> **要点**：流程框架对前锋 / 守门员是统一的；二者差异完全收敛在 `PLAY` 下按 `player_role`
> 选择的子树里。而 `player_role` 本身由团队层动态决定（§5.4）。`ReactiveSequence` 每 tick
> 重评 `_while` 条件，所以裁判机状态一变，行为立即切换。

## 3. 单机策略

### 3.1 前锋：`subtree_striker_play.xml` + `StrikerDecide`（`brain_tree.cpp:961`）

**子树每 tick 流程**：

```
SelfLocate(trust_direction) → Locate(decision!='find' 时)
├─ wait_for_opponent_kickoff → 仅 找球 + 停车（规则：对方开球前不得碰球）
└─ 正常比赛
   ├─ ball_out → 找球 + GoBackInField（回场内）
   └─ !ball_out → CamFindAndTrackBall → CalcKickDir → StrikerDecide → 按 decision 执行：
        find             → FindBall 子树
        assist           → Assist            (vx≤0.5, vy≤0.5)
        chase            → Chase             (vx≤0.9, vy≤0.2)
        auto_visual_kick → RLVisionKick      (RL 视觉踢球)
        adjust           → Adjust            (绕球微调对位)
        kick             → Kick              (speed≤0.9, 射门)
        cross            → Kick              (speed≤0.6, 传中)
```

**`StrikerDecide::tick()` 决策优先级**（自上而下短路；条件均为代码实测）：

| 优先级 | decision | 触发条件（核对自 `brain_tree.cpp:1050-1106`） |
|:--:|----|----|
| 1 | `find` | `!(ball_location_known \|\| tm_ball_pos_reliable)`——我和队友都不知道球 |
| 2 | `auto_visual_kick` | `enable_auto_visual_kick` 且 `tmImLead` 且 **`tmMyCostRank==0`** 且 `!ball_out` 且 `!lose_ball` 且 `tmMyCost<7.0` 且 `0.2<ballRange<4.0` 且 `\|ballYaw\|<0.8×1.3` 且 球与自身均"在场内"（`x>length/2−14.3 && \|y\|<5.0`，对常规场尺寸近乎恒真，本质是"未严重错定位"的护栏） |
| 3 | `assist` | **`!tmImLead`**——我不是控球主力 → 让位接应（团队耦合点） |
| 4 | `chase` | `ballRange > chase_threshold × (上次是 chase ? 0.9 : 1.0)`，0.9 为滞回防抖 |
| 5 | `kick` / `cross` / `safe_shoot` | `((angleGoodForKick && !isFreekickKickingOff) \|\| 已转过 kickDir)` 且 `!avoidKick` 且 `ballDetected` 且 `\|ball.yawToRobot\| < KICK_THETA_RANGE(=0.2)` 且 `ball.range < KICK_RANGE(=1.0)`。其中 `kickType=='cross'→cross`；否则 `threatLevel<threat_threshold(−2.0) ? safe_shoot : kick` |
| 6 | `adjust` | 以上都不满足（默认）：绕球调整到 `kickDir` |

要点与陷阱：
- **`KICK_THETA_RANGE` 实际值是 `0.2`**（config 覆盖了代码里的字面默认 `1.5`，见 `config.yaml:74`）。读代码时勿被 `brain_tree.cpp:976` 的 `1.5` 误导。
- 第 5 档的 **`safe_shoot` 是死分支**：`threatLevel()` 返回 `{0,1,2}`（≥0），而 `threat_threshold=−2.0`，`threatLevel < −2.0` 恒为假 → 永不产生 `safe_shoot`；且子树也未给它配动作节点（双重失效）。
- 决策 2、3 直接依赖团队状态（`tmImLead`、`tmMyCostRank`），是单机 ↔ 团队的**主耦合点**。
- `kickValue()`（`brain.cpp:3756`）只用于屏幕日志展示，不参与分支判断。

**踢球方向 `CalcKickDir::tick()`（`brain_tree.cpp:893`）**——决定 `kickType` 与 `kickDir`：

| kickType | 触发 | 方向 |
|----|----|----|
| `cross`（传中） | 射门角太窄（`θl−θr<cross_threshold`）且球已过中圈；或开球时（`isFreekickKickingOff && isPrimaryStriker && !isDirectShoot`）球在中场 | 往禁区 / 往另一侧传 |
| `block`（解围） | `isDefensing()`（正在防守对方任意球，`brain.cpp:1587`） | 沿"球→远离己门"方向 |
| `shoot`（默认） | 其余 | 朝对方球门中心；球已过底线则直接向前（`kickDir=0`） |

### 3.2 守门员：`subtree_goal_keeper_play.xml` + `GoalieDecide`（`brain_tree.cpp:1129`）

子树按 `goalie_mode` 分两态：
- **`attack`**：`GoalieDecide` 输出 `decision` → 出击 / 回防 / 解围。
- **`guard`**：`!ball_location_known → GoToReadyPosition`，否则 `GoToGoalBlockingPosition`。

> ⚠ **重要核对**：`goalie_mode` 在 `brain_tree.cpp:122` 初始化为 `"attack"`，全代码**仅** `Intercept`
> 节点会把它复位为 `"attack"`（`:1571 / :1612`），**没有任何地方把它置为 `"guard"`**。而
> `Intercept` 虽已注册实现（`:1534`），却**未被任何行为树引用**。因此在当前 `game.xml` 流程下，
> **守门员恒处于 `attack` 态，`guard` 分支不可达**。（既有报告把 guard 描述为活动态，与现状不符。）

**`GoalieDecide::tick()` 决策优先级**（核对自 `brain_tree.cpp:1161-1195`）：

| 优先级 | decision | 条件 | 动作 |
|:--:|----|----|----|
| 1 | `find` | `!(ball_location_known \|\| tm_ball_pos_reliable)` | `GoToGoalBlockingPosition`（边封门边找） |
| 2 | `retreat` | `ball.posToField.x > 0 − (上次是 retreat ? 1 : 0)`（球在对方半场，滞回到 x<−1 才退出） | `GoToGoalBlockingPosition`（回防） |
| 3 | `chase` | `ballRange > chase_threshold × 滞回` | `Chase`（守门 vx≤1.5，比前锋更激进） |
| 4 | `kick` | `angleIsGood`：`dir_rb_f ∈ (−π/2, π/2)` | `Kick`（speed≤1.2，大力解围） |
| 5 | `adjust` | 默认 | `Adjust` |

> 注：`GoalieDecide` 第 3 档之间有一段"自动视觉扑救"`else if`（`:1171`，受 `enable_auto_visual_defend`
> 控制），其分支体已被删空、**不设置 `decision`**。所幸 `enable_auto_visual_defend` 默认 `false`，
> 该分支不会进入；但若误开此参数，会进入空分支并沿用上一帧 `decision`——属潜在隐患。

### 3.3 公共单机子流程

- **等待对方开球**（`updateKickoffMemory()` `brain.cpp:1264`）：处于 `SET`/`READY`（或任意球 `SET`/`GET_READY`）
  且**非己方开球方**时置 `wait_for_opponent_kickoff=true`，记录当前球位与时间；直到**球位移超过阈值**
  `max(0.15×range, 0.3m)` 或**超时 10s** 才解除。期间只找球 + 站定。
- **出界**（`updateBallOut()` `brain.cpp:1495` + `isBallOut()` `:1470`）：综合"定位越界"与"视觉边线距离"，
  带滞回放宽（上次出界用 1.0×、否则 1.5× 阈值；任意球期间再 +1.0）。出界后前锋 `GoBackInField` 回场。
- **任意球**（`StrikerFreekick` / `GoalKeeperFreekick`）：前锋按 **cost 排名**走攻 / 防站位
  （`GoToFreekickPosition`，§5.6）；守门员回 `GoToReadyPosition` / `GoToGoalBlockingPosition`。
- **自动起身**（`CheckAndStandUp` `brain_tree.cpp:3384`）：摔倒（`HAS_FALLEN` 且 damping 态）则
  `standUp()`，受 `recovery.retry_max_count(=2)` 限制重试次数。

## 4. 团队策略

全部协同决策集中在 `Brain::handleCooperation()`（`brain.cpp:925`），每 tick 调用一次。

### 4.1 通讯架构（`brain_communication.cpp`，常量核对自 `brain_communication.h`）

总开关 `enable_com`（config 默认 `True`）。`BrainCommunication` 起 5 个线程：

| 通道 | 端口 | 周期 / 超时 | 作用 |
|----|----|----|----|
| Discovery 广播 | `20000+teamId` | 1000ms | 广播自身 `playerId`，让队友发现我的 IP |
| Discovery 接收 | 同上 | 维护 IP→队友映射，**20s** 超时清除（`TEAMMATE_TIMEOUT_MS`） | 发现队友地址 |
| Communication 单播 | `30000+teamId` | **100ms**（`UNICAST_INTERVAL_MS`） | 向每个已知队友发完整 `TeamCommunicationMsg` |
| Communication 接收 | 同上 | — | 解析队友消息，写 `data->tmStatus[playerId−1]` |
| GameController 单播 | `GAMECONTROLLER_RETURN_PORT` | 1000ms | 向裁判机回报存活 |

接收端过滤：`validation`（通讯 `31202` / 发现 `41203`）、`teamId` 不符、自己的包、`playerId` 越界、
**替补（`SUBSTITUTE`）队员**一律忽略；当收到 `cmdId` 比本地新时，把 `cmd` 转交主循环处理（`:537-542`）。

### 4.2 报文 `TeamCommunicationMsg`（`team_communication_msg.h`）核心字段

```c
int    playerRole;        // 1:striker 2:goal_keeper
bool   isAlive;           // 在场且未罚时
bool   isLead;            // 是否控球主力
bool   ballDetected / ballLocationKnown;
double ballConfidence / ballRange / cost;   // cost ≈ 我踢到球所需"秒数"
Point  ballPosToField;    Pose2D robotPoseToField;
double kickDir;  double thetaRb;
int    cmdId;  int cmd;   // 协同指令（见 4.5）
```

### 4.3 控球成本 `updateCostToKick()`（`brain.cpp:1348`）——分工度量基础

把"我接近并踢到球的难度"折算成一个**约等于秒数**的标量，**精确公式**：

```
cost  = secsSinceBallDet                                  // 距上次看到球的秒数
      + (ball_location_known ? 0 : 5.0)                   // 球位未知
      + ball.range                                        // 球距
      + (distToObstacle(ball.yaw) < 1.5 ? 0.5 : 0)        // 球方向上有障碍(注:日志打印 2.0 但实加 0.5)
      + |ball.yawToRobot|                                 // 需要转身的角度
      + Σ_alive队友 (该队友更近 且 横向间距<1.0m ? 2.0 : 0) // "撞队友"惩罚, 避免抢同一个球
      + |kickDir − robotBallAngle| × 0.4/0.3 (≈ ×1.333)   // 需要绕球对位的角度
      + (HAS_FALLEN ? 15.0 : 0)                           // 摔倒
      + (!odom_calibrated ? 100 : 0)                      // 未定位 → 基本退出竞争
tmMyCost = 0.8 × 上次cost + 0.2 × cost                    // 平滑
```

> `+100`（未定位）意味着**任一机器人定位失败会立刻退出控球竞争**——合理的安全设计，也说明
> 定位稳定性直接决定团队分工是否正常，是比赛关键风险点。

### 4.4 控球权（lead）与排名（`brain.cpp:1063-1092`）

```
tmMinCost      = 全队(含自己)最低 cost
myCostRank     = cost 比我低的"存活"队友数（0 = 我最该上球）
myStrikerIDRank= playerId 比我小的"存活前锋"数（固定站位分工用）

若 (tmMinCost < ball_control_cost_threshold[=5.0] 且 myCost > tmMinCost) 或 myCostRank >= 2
     → tmImLead = false （我去 assist 接应）
否则 → tmImLead = true  （我去 chase / kick）
```

效果：**cost 最低者控球进攻，其余前锋转 `assist`**，避免一拥而上；`myCostRank>=2` 保证最多 2 人争球。

### 4.5 角色动态切换与守门员↔前锋交接

**(a) 基于人数的角色重排**（`handleCooperation` `brain.cpp:1041-1060` + `brain.cpp:1158-1165`）：
> 原则：**只有满员时才保留守门员，其余情况全员进攻。**
- 我未罚时 且 存活数 < 总人数 → 强制 `striker`；
- 我在罚时 且 其他人全活（存活数 == 总人数−1）→ 我（回场后）当 `goal_keeper`；
- `INITIAL` → 复位为 config 初始角色；
- `READY`/`GET_READY` 且满员 → 复位为 config 初始角色。

> ⚠ `RoleSwitchIfNeeded` 节点（`brain_tree.cpp:3428`）实现了**几乎相同**的规则，但**未被任何行为树引用**
> （已 grep 确认）——即真正生效的只有 `handleCooperation` 里这套，节点是冗余/历史遗留。

**(b) 守门员主动出击交接**（`brain.cpp:1096-1129`）：当我是"存活 + 恰成控球主力的守门员"且距上次发令 >2s：
- 计算各活着队友到**己方球门**的距离，取最近者 `minIndex`、最远距离 `maxDist`；
- 若**我离门最远**（`myDist > maxDist`）→ 立即 `player_role="striker"` 出击，并发指令
  `cmd = 10 + (minIndex+1)` 请最近队友接替守门。

**(c) 指令处理 / 协议**（接收端 `brain.cpp:1132-1154`）：
- `cmd == 100`：队友宣告控球 → 我 `tmImLead=false` 去 assist。
- `cmd ∈ (10,20)`：守门请求出击，`newGoalieId = cmd−10`；若指我 → 我接任 `goal_keeper`。

> ⚠ 核对：**当前唯一被实际"发送"的指令是 (b) 的 `10+id`**（`tmMyCmd` 仅在 `brain.cpp:1121` 赋值）。
> `cmd==100` 的接收逻辑存在，但**没有任何发送方**——lead/assist 的分配实际上完全由 §4.4 的 cost 排名
> 驱动，`cmd==100` 是定义了但当前未触发的协议路径。

### 4.6 站位协同（按排名摊开，避免重叠）

| 场景 | 节点（行号） | 分工依据 | 站位摘要 |
|----|----|----|----|
| 进攻接应 | `Assist`（`brain_tree.cpp:720`） | `tmMyCostRank` | rank0/1：球后 2m、堵在"球→己门"连线上；rank2：禁区前沿+1m；rank3：禁区前沿；rank≥4：兜底防守位 |
| 任意球 | `GoToFreekickPosition`（`brain_tree.cpp:524`） | `tmMyCostRank` | 攻 rank0=主罚（球后 0.7m 朝 kickDir）、rank1=后插 2m、rank2/3=禁区两角；防 rank0/1 拉开纵深、rank2/3 守角 |
| 开球就位 | `GoToReadyPosition`（`brain_tree.cpp:3272`） | `myStrikerIDRank` | 前锋 rank0=中圈前、rank1=偏 y、rank2/3=后场；守门=小禁区中央 |
| 封门 | `GoToGoalBlockingPosition`（`brain_tree.cpp:658`） | `player_role` | 站"球→己门"连线上；守门贴门线（y 限 penaltyAreaWidth），前锋可前压（y 限 goalWidth） |

> 进攻 / 任意球用 **cost 排名**（动态，谁该上谁上）；开球就位用 **ID 排名**（固定、可预测）——刻意区分。
> （`GoToFreekickPosition` 代码注释明确："和 assist 对齐：freekick 按 tmMyCostRank 分工，不再按前锋序号"。）

### 4.7 队友球信息共享（`brain.cpp:1000-1039`）

自己看不到球时，采纳**距自己足够远**（>`tm_ball_dist_threshold=1.5m`，避免与自己视野冲突）的队友报告的球位，
取其中 `ballRange` 最小者，置 `tm_ball_pos_reliable=true`，供 `find` 判定与任意球站位使用；1s 无可信队友球则失效。

## 7. 代码核对发现与差异（相对 `2026-06-18_单机与团队策略分析.md`）

1. **行号整体下移约 +14**：`StrikerDecide` 947→**961**、`GoalieDecide` 1115→**1129**、`Assist` 706→**720**、
   `GoToFreekickPosition` 504→**518/524**、`GoToGoalBlockingPosition` 644→**658**、`GoToReadyPosition` 3258→**3272**、
   `CalcKickDir` 879→**893**、`RoleSwitchIfNeeded` 3414→**3428**。本报告行号已重新核对。
2. **守门员 `guard` 态不可达**：`goalie_mode` 恒为 `attack`（无处置 `guard`），且 `Intercept` 未被任何
   行为树引用。既有报告把 guard / Intercept 描述为活动逻辑，与现状不符。
3. **`safe_shoot` 双重失效**：`threatLevel()≥0` 而阈值 `−2.0` → 永不产生；子树亦无对应节点。
4. **`RoleSwitchIfNeeded` 节点未被引用**：真正生效的角色切换只在 `handleCooperation`，节点是冗余。
5. **`cmd==100` 无发送方**：唯一实际发送的协同指令是守门→前锋交接 `10+id`；控球分配实际只靠 cost 排名。
6. **`KICK_THETA_RANGE` 实际为 0.2**（config 覆盖代码字面 1.5）；`updateCostToKick` 障碍项实加 0.5（日志打印 2.0）。

## 8. 风险与优化建议

1. **清理失效分支**：`safe_shoot`、`goalie_mode=='guard'`、`Intercept`、`RoleSwitchIfNeeded`、
   `enable_auto_visual_defend` 空分支——要么补全、要么删除，避免日后调阈值/改逻辑时出现"无动作"或行为不一致。
2. **角色切换逻辑收敛**：把 `handleCooperation` 与 `RoleSwitchIfNeeded` 的重复规则统一到一处。
3. **协同超时分层**需分别确认：地址发现 20s、协同存活 `COM_TIMEOUT=5s`、队友球位 1s、队友指令冷却 2s。
4. **定位是分工命脉**：`+100` 未定位惩罚会令该机退出控球竞争——比赛中优先保证定位稳定。
5. **统一文档**：本报告与 `2026-06-18_单机与团队策略分析.md` 高度重叠，建议保留其一（本报告行号/分支更新），避免维护分叉。
