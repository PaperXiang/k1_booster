## 1. 正确性审核（验证了什么，怎么验证的）

### 1.1 坐标变换约定（P2-1 的命根子）
`locator.cpp:markerToFieldFrame` 与 `math.h:transCoord` 均为 **`field = R(θ)·robot + (x,y)`，R 为标准逆时针旋转**。
- `SelfLocateCircle` 的位置解 `t = −R(θ)·M_r`、朝向解 `θ = ±π/2 − β` **正是这套约定**。
- 手算验证：机器人在 (0,−2) 朝 +x、中圈在 (0,0)，两 X 在 (0,±R)，代入可正确解回 `(0,−2,0)`；且对两点顺序无关。
- `residual(markers_r, pose)` 内部就是用 `markerToFieldFrame` 把机器人系地标按 `pose` 投到场地系比对地图——我传入的 `allMarkers`(机器人系)+`hypoPose`(机器人场地位姿) **语义一致**。
✅ 结论：Circle 的数学与既有定位体系**完全自洽**，非幻觉。

### 1.2 没有虚构 API
Circle 用到的 `getMarkingsByType / posToRobot / range / calibrateOdom(x,y,θ) / locator->residual / residualTolerance / isStandingStill / toPInPI / norm / cap` 全部是既有校正器（2X/1P/Border）在用的同名接口，签名一致。✅

### 1.3 P1-1 各修复
- `SelfLocate2X`：`dx=−(p0+p1)/2` 已对，`dy` 原写成 `−(p1+p1)/2`（少了 p0），修为 `−(p0+p1)/2`。语义=把"观测到的中圈中心"对齐到地图 (0,0)。✅ **此节点在 `subtree_locate.xml` 中生效**。
- `SelfLocateLT`：外层 `tMarkers`、内层 `lMarkers`（不同数组），原 `j=i+1` 会跳过 `lMarkers[0]`（只有 1 个 L 时直接漏配）→ 改 `j=0`。循环体命中首个合法 (T,L) 即 break，遍历全对是对的。✅
- `SelfLocatePT`、`_doubleX`、`getMarkersForLocator`：见 §2 的"比赛意义"，修复本身正确。

## 2. 是否符合真实比赛（有用 vs 冗余/休眠）

诚实结论：**P1-1 五处修复里，真正"既正确又当前生效又有实效"的是 `SelfLocate2X` 和 `SelfLocateLT`；另三处正确但实效有限**：

1. **`SelfLocatePT`（实为 goalpost+T，非罚球点+T）**：审核中发现它疑似有**历史 bug**——`pos_m.x = half * fd.length`（看起来应为 `fd.length/2`），导致 T 的地图位置落到场外 ±14m，观测值永远匹配不上 → 该节点很可能**从不触发**。我的 `j=0` 修复对循环本身正确，但被这个历史 bug 压住，**实效存疑**。
2. **`_doubleX`（属 `SelfLocateLocal`）**：① `SelfLocateLocal` **不在 `subtree_locate.xml` 级联**（注册了但没用，类似 RoleSwitchIfNeeded）；② `_doubleX` 另有历史 bug——`fabs(p0.y−p1.y) > 0.3` 判"方向不对"与下一行"间距≈中圈直径"自相矛盾（adult 场永不通过），疑似该写 `.x`。→ 我的 yc 修复正确但是**死路**。
3. **`getMarkersForLocator` 初始化**：正确的健壮性兜底，但上游 `getMarkings()` 通常只产出 4 类合法地标 → 实际很少触发，**影响小**。

> 这些**历史 bug 不是本次引入的**，我**没有顺手改**（避免在未验证基础上再堆改动）。建议作为后续单独变更评估（见 §6）。

**P2-1 `SelfLocateCircle` 是否冗余？** 不冗余：它是**唯一在比赛中纠正朝向 θ** 的校正器，其余几何校正器全部只纠平移。直击团队自评"定位极差/朝向锁死"的最大短板。触发条件：中圈+中线两个 X 同时入镜(约 ≤5m、面向中圈)，常见于开球、丢球后、中场。**实效取决于视觉对中圈两 X 的检出质量**——这是团队已知的薄弱环节，故能不能用，得上机/仿真看日志（见 §4）。

## 4. 如何测试与启用

**P1（已默认生效，先 build 验证不回归）**
1. `colcon build --packages-select brain`（动了 brain_tree/brain_data/brain_config/robot_client）。
2. `ros2 launch brain launch.py tree:=game.xml` 起树**不崩**。
3. 仿真/回放：看定位是否更少跳变；WebUI `R+朝向线` 是否更贴合、`ms_since_localize` 是否更短。
4. 头部：找球/起身时头不顶限位卡顿；漏脚下近球 → 调大 `brain_config.h` 的 `headPitchLimitDown`(≤1.0) 重编。

**P2-1 `SelfLocateCircle`（默认不挂，分两步灰度）**
1. **先不挂级联**：build 后起树确认注册不报错。站到能看中圈处，看日志 `/locate/circle/success|fail`——是否在合理时给 success，`posDrift/thetaDrift` 是否合理。
2. **确认合理后启用**：在 `subtree_locate.xml` 取消那行 `<SelfLocateCircle msecs_interval="300" max_dist="5.0" max_drift="3.5" max_theta_drift="0.6" />` 注释（放在平移校正器之前，顺序即优先级）。
3. 仿真/回放看朝向漂移是否被纠回；不稳就重新注释回退（无需改 C++）。

## 5. 道理（为什么这么做）

- **定位是分工命脉**：cost 里未定位 +100 直接退出控球竞争（`brain.cpp:1502`），所以定位准不准直接决定团队能不能正常踢。先修 bug、再补朝向校正，性价比最高。
- **朝向为什么单独补**：原系统刻意"比赛中只纠平移、朝向交给陀螺"以求位姿连续；但陀螺会漂、会打滑，一旦朝向歪了，平移校正反而把误差"锁"在错方向。Circle 用中圈+中线一次解出含朝向的全局位姿，正是补这个洞。
- **为什么默认不挂 / 开关化**：上次 0618 把没实现的节点写进 XML 直接让 game.xml 崩了。这次"实现+注册+默认不挂"，先看日志再灰度，杜绝重蹈覆辙，也符合"1h 测试、可回退"的纪律。
- **为什么不顺手修发现的历史 bug**：审核目的是看清现状；在未验证的基础上再堆改动会放大风险。把它们列出来交你决定，比偷偷改更安全。
