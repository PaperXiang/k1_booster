# 0618 后变更测试优先级图谱

日期：2026-06-25

用途：把 0618 以后已经改过的内容按“会不会干废比赛、能不能开关、应该先测什么”压缩成一张可执行测试图谱。此文档是测试索引，不替代具体代码审查；最终开关值以当前 `config.yaml`、行为树 XML 和启动参数为准。

## 1. 一句话结论

最容易把比赛直接打崩的不是 WebUI 或注释类改动，而是这五类：

1. 找球/头部扫描重写：找不到球，后面全部策略都失效。
2. 比赛状态与开球/任意球计时：对比后未确认核心流程被改，但它是必须回归的 S 级规则风险；提前动会违规，不动会白给。
3. Chase 弧线追球：速度和转向耦合变了，可能冲过球或绕圈。
4. 球路预测用于追球：如果追的是错误预测球，会系统性跑偏。
5. 队友球共享启用后：可能相信过期队友球，整队追假球。

## 2. 等级定义

### 测试优先级

| 等级 | 含义 | 应该什么时候做 |
|---|---|---|
| P0 | 先测；不上场也能发现大雷 | 立刻补单测/起树/回放，赛前必须过最小验证 |
| P1 | 再测；需要仿真、回放或短场地验证 | P0 过后做，覆盖运动和行为树序列 |
| P2 | 最后测；辅助链路或当前未接线 | 不应阻塞比赛，除非发现影响主进程性能 |

### 破坏性等级

| 等级 | 含义 | 典型后果 |
|---|---|---|
| S | 可直接干废比赛 | 机器人不动、违规动、找不到球、追错球 |
| A | 会显著改变比赛行为 | 运动轨迹/定位/扫描覆盖变化，可能造成局部失效 |
| B | 主要影响验证或辅助 | 遥测不准、图显示错、日志影响调试 |
| C | 当前运行影响低 | 未接线、纯注释、只影响未来接入 |

## 4. 推荐测试执行顺序

### 第 0 轮：先做 P0，不碰机器人也能测

1. 起树/加载检查
   - 目标：防止再次出现行为树 XML 引用了未注册节点导致启动崩溃。
   - 最小通过标准：`game.xml`、关键 subtree 能加载；默认配置能启动 brain。

2. `k1_teammate_ball` 纯逻辑测试
   - 覆盖：`enable=false`、`teammate_timeout`、`trust_timeout`、等于阈值边界、旧时间戳、未来时间戳、`reset()`。
   - 原因：无 ROS 依赖，成本低；启用后破坏性不低。

3. `k1_ball_predictor` 时间测试
   - 覆盖：`dt < 0`、`dt == 0`、`dt < min_dt`、`dt == min_dt`、`dt == max_dt`、`dt > max_dt`、`dt > max_history_gap`、丢球 `lost_prediction_timeout`。
   - 原因：如果预测接管 chase，错误时间戳会直接变成错误追球目标。

4. `StrikerDecide` / Adjust timeout 测试
   - 覆盖：`adjust_timeout_secs=0` 关闭、未超时、刚好超时、超过阈值、离开 adjust 后清零。
   - 注意：文档中曾写默认关；若当前 `config.yaml` 已设为大于 0，则它已经在默认配置里生效，赛前必须复核。

5. 开球/任意球计时最小回归测试
   - 覆盖：对方开球球没动且未到 10s 不应动；球动了应解除；超过 10s 应解除。
   - 原因：这是规则层风险，错了不是“效果差”，而是可能直接违规。

### 第 1 轮：P1，仿真/回放/短场地 smoke

1. 找球扫描序列
   - `CamFindBall`：799ms 不切、800ms 切、长时间重启。
   - `CamFastScan`：`msecs_interval` 边界。
   - `CamLissajousScan`：周期、相位、头部限位后是否仍覆盖。
   - `RobotFindBall`：稳定检测计数、找到球早退。

2. Chase 弧线追球
   - `arc_walk=false`：确认回原行为。
   - `arc_walk=true`：不同角度下前向速度不超过上限，近球不明显过冲。

3. 头部 DOF clamp
   - 确认所有头部命令都在安全范围内。
   - 重点观察低头/偏航收紧后是否丢边缘球和近球。

4. 定位修复 / SelfLocateCircle/PT
   - 默认不挂级联时，不应改变比赛主行为。
   - 若启用，必须看 pose 是否跳变、是否能恢复。

### 第 2 轮：P2，辅助链路与未来接线

1. WebUI / FieldView
   - 验证 telemetry 不影响主进程；请求失败有 5s 限流，不刷屏。

2. 拦截时间解算
   - 当前未接线时只需要 CI/数学边界；未来接入守门员或追球前，再升为 P0/P1。

3. 日志、通信、RobotClient sleep
   - 验证不会阻塞主循环或造成明显性能抖动。

## 5. 赛前开关与回退清单

| 如果现象是 | 优先回退/开关 | 备注 |
|---|---|---|
| 追球冲过球、绕圈、速度太激进 | `arc_walk=false`，必要时降 chase 速度上限 | 弧线追球是运动行为大改 |
| Adjust 绕球过早退出或仍卡死 | `strategy.adjust_timeout_secs=0` 关闭，或调大/调小阈值 | 先确认当前 config 实际值 |
| 追错预测球、丢球后跑偏 | `ball_prediction.use_for_chase=false`，必要时 `enable=false` | 保留预测显示可以，先别让它接管 chase |
| 多机器人追假球 | `teammate_ball_share.enable=false` | 队友球共享默认关闭最安全 |
| 找不到球或找球卡住 | 回退 `subtree_find_ball.xml` / 找球节点改动 | 这是无单参数开关的高风险项 |
| 头部看不到边缘球/近球 | 复核 head DOF clamp 和扫描点 | 安全限制不能直接关，需谨慎回退 |
| 定位突然跳变 | 保持 SelfLocateCircle/PT 不挂级联 | 定位类问题会放大到全策略 |
| WebUI 显示错或请求失败 | 不依赖 WebUI 做比赛决策 | 一般不应阻塞比赛 |

## 6. Go / No-Go 规则

- S 级任一项没过最小验证，不建议进正式比赛配置。
- 有开关的功能，赛前要保留明确回退值，并记录当前实际配置。
- 无简单开关的改动，必须至少做起树、回放或短场地 smoke。
- WebUI、日志、可视化类问题不应阻塞比赛，除非确认影响 brain 主循环性能。
- 当前未接线的拦截解算不应作为赛前阻塞项；一旦接线，立刻升为高优先级测试。
