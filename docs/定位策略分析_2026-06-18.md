# K1 Booster 1.6 机器人自定位（Localization）策略分析报告

> 日期：2026-06-18 ｜ 范围：`src/brain`（策略/定位）与 `src/vision`（投影前端）
> 目的：完整梳理当前代码中机器人“在球场坐标系下确定自身位姿”的整体策略、算法、触发时机与风险。

---

## 1. 摘要

当前定位系统是一套 **“里程计高频递推 + 视觉地标低频校正”** 的混合架构，本质等价于 ROS 经典的 `map → odom → base_link` 变换树（REP‑105）：

- **里程计（Odometer / IMU）** 以高频提供平滑、连续但会缓慢漂移的 `robotPoseToOdom`。
- **视觉地标定位** 在球场坐标系中测量机器人真实位姿，并据此反解 `odomToField`（即 map→odom 变换），从而“校准”里程计漂移。
- 两者复合得到最终对外使用的 `robotPoseToField`。

视觉校正本身又分两层：

1. **全局粒子滤波定位器 `Locator`**（`SelfLocate` 节点）——可在较大范围内求解完整位姿 `(x, y, θ)`。
2. **一组几何/场线增量校正器 `SelfLocate*` 家族**——利用特定地标组合（罚球点、X/T/L 交叉点、边线/球门线/中线）做**仅平移 `(dx, dy)`** 的快速纠偏，并用全部地标残差做一致性校验。

> **核心设计取向**：朝向角 `θ` 主要依赖里程计/陀螺仪“可信”，仅在入场/重定位时由粒子滤波重设；比赛进行中几乎只校正平移，不校正朝向（见 §6、§11）。

## 3. 坐标系模型与里程计融合（map → odom → base）

系统维护三个 2D 位姿（`Pose2D{x, y, θ}`，θ 自 x 轴正向逆时针为正）：

- `robotPoseToOdom`：机器人在**里程计系**的位姿，来自 `/odometer_state`（`odometerCallback`，`brain.cpp:2272`），并乘以标定因子 `robot.odom_factor`（config 中为 `1.2`）。
- `odomToField`：**里程计系→球场系**的变换，是定位真正要估计/校准的量。
- `robotPoseToField`：对外使用的机器人**球场系**位姿 = `odomToField ∘ robotPoseToOdom`，每次里程计回调都重算（`brain.cpp:2280`）。

**校准过程 `calibrateOdom(x, y, θ)`（`brain.cpp:1665`）**：给定一次视觉测得的球场位姿，先求 `robotPoseToOdom` 的逆（odom→robot），再与目标位姿复合，反解出新的 `odomToField`；随后立即用新变换刷新 `robotPoseToField` 以及球、机器人、球门、地标等所有对象的球场坐标。

> 等价语义：定位只“纠正 map→odom”，而 odom→base 由高频里程计平滑提供。两次校正之间，机器人靠里程计推算，位姿连续无跳变。

`odom_calibrated`（行为树黑板布尔量）标记“当前位姿是否可信”：
- 初始为 `false`（`brain_tree.cpp:105`）；
- 被判罚/需重新入场时重置为 `false`（`brain.cpp:2044`）；
- 任一全局定位成功后置 `true`（如 `brain_tree.cpp:1994`）。
- 未校准时，行为树先执行 `CamScanField`（扫视收集地标），校准后才转入找球/比赛。

## 4. 感知前端：地标与场线

### 4.1 地标（Markings）

视觉输出的每个检测对象，其机器人系坐标直接取自 **固定地面投影** `position_projection`（`brain.cpp:2715`，即相机射线与 `z=0` 平面求交；深度测距分支被注释停用）。由此计算 `range`、`yaw`、`pitch`（pitch 用 `robotHeight=0.90` 近似）。

`detectProcessMarkings`（`brain.cpp:2828`）过滤低置信度与异常距离（`x ∈ [-0.5, 15] m`），再 `identifyMarking` 给每个地标赋予地图 id：
- 在 `config->mapMarkings` 中找**同类型**最近点（`identifyMarking`，`brain.cpp:2568`）；
- 仅当 **最近距离 < 阈值** 且 **次近-最近 > 间隔阈值**（阈值随场地尺寸缩放 `1.5 * 14 / length`）才接受，保证“唯一可辨识”，否则 id = -1。

地标类型与字符映射（`getMarkersForLocator`，`brain_data.cpp:22`）：`LCross→'L'`、`TCross→'T'`、`XCross→'X'`、`PenaltyPoint→'P'`。

### 4.2 球场地标地图

两处生成理论地标坐标（应保持一致）：
- `Locator::calcFieldMarkers`（`locator.cpp:23`）：中圈 X、罚球点 P、边线/禁区/球门区/四角的 L、T 点。
- `BrainConfig::calcMapMarkings`（`brain_config.cpp:146`）：带可读 `name`（四位编码，如 `LSCL`）的地图点，供 `identifyMarking` 使用。

当前场地：`field_type: adult_size`（`FD_ADULTSIZE = {14.16, 9.22, …}`，`types.h:34`）。

### 4.3 场线（FieldLines）

`processFieldLines`（`brain.cpp:2621`）合并重复线、按方向（水平/垂直，阈值 0.1 rad）过滤、按长度（>0.2 m）筛除，再 `identifyFieldLine` 标注类型（TouchLine/GoalLine/MiddleLine/GoalArea/PenaltyArea）、半场、左右。供 `SelfLocateBorder`、`SelfLocateLine` 使用。

## 5. 全局定位器：粒子滤波 `Locator`

文件：`locator.cpp` / `locator.h`。算法为 **迭代收缩式蒙特卡洛定位（粒子滤波 + 渐进式重采样）**。

**输入**：机器人系地标 `markers_r`、约束盒 `PoseBox2D{x,y,θ 范围}`、粒子数（默认 200）。

**流程**（`locateRobot`，`locator.cpp:280`）：
1. 地标数 < `minMarkerCnt`（config=4）→ 失败 code=4。
2. `genInitialParticles`：在约束盒内**均匀随机**撒粒子（`locator.cpp:81`）。
3. `calcProbs`（`locator.cpp:225`）：对每个粒子，把观测地标变换到球场系，计算**残差** `residual`，再用高斯密度赋权并归一化为概率：
   - 残差（`locator.cpp:185`）：`Σ minDist(同类型最近地图地标) / range * 3` —— **按 1/距离加权**，近处地标拟合权重更大（远处投影误差大、被弱化）。
   - 概率分布均值 `μ = min(residual) - muOffset·σ`，残差越小概率越高。
4. 迭代（最多 `maxIteration=20`）：
   - `isConverged`：当所有粒子 x/y/θ 极差均 < `convergeTolerance=0.2` → 收敛。
   - 收敛后若 **平均残差 > `residualTolerance`（config=0.4）** → 判为不合理，失败 code=2；否则成功，返回 `bestPose`。
   - 未收敛则 `genParticles`（`locator.cpp:98`）：按累计概率重采样，粒子数 ×`0.85`、扰动幅度 ×`0.8` 逐轮收缩，并裁剪回约束盒。
5. 返回码：`0 成功 / 1 生成粒子失败 / 2 残差不合理 / 3 未收敛 / 4 地标不足 / 5 概率全为 0`。

> 备注：`finalAdjust`（基于最近地标重定 x,y）已实现但在 `locateRobot` 中被**注释停用**（`locator.cpp:327`）。

**约束盒（mode）决定搜索范围与是否解算朝向**（`SelfLocate::tick`，`brain_tree.cpp:1866`）：

| mode | x/y 范围 | θ 范围 | 用途 |
|---|---|---|---|
| `enter_field` | 己方半场、边线外 1 m 内 | 面向场内 ±30°（约 ±90° 附近） | 入场/被判罚后重定位 |
| `face_forward` | 全场 | ±45° | 面向前方的全局定位 |
| `trust_direction` | 当前位姿 ± 漂移上限(0.1 m/s×时间) | **当前 θ ±1°** | 比赛中持续微调（朝向几乎冻结） |
| `fall_recovery` | 全场+2 m | **当前 θ ±1°** | 摔倒起身后 |

`SelfLocateEnterField`（`brain_tree.cpp:2003`）则同时尝试左/右入场两个约束盒，取残差更优者，免去手动指定 `playerStartPos`。

## 6. 局部增量校正器级联（`SelfLocate*` 家族）

这是**比赛进行中的主力**。它们共享统一范式（以 `SelfLocate1M`/`2X`/`2T`/`LT`/`PT` 为例）：

```text
1. 频率闸门：距上次成功定位 < msecs_interval(300ms) 则跳过
2. 取特定地标组合；静止时(isStandingStill) maxDist 放大 1.5×
3. 几何自检：组合的相对距离/方向是否符合地图（剔除误检）
4. 地图匹配：在 maxDrift 内匹配到唯一地图位置
5. 计算“理论 - 实际”的平移量 (dx, dy)，得到候选位姿 hypoPose
6. 一致性校验：用【全部】地标算平均残差，> residualTolerance(0.4) 则拒绝
7. 通过 → calibrateOdom(hypoPose)，刷新 lastSuccessfulLocalizeTime
```

> **共同特征（关键）**：所有几何校正器**只修正平移 `(dx, dy)`，从不修正朝向 `θ`**（`hypoPose.theta` 原样保留）。即比赛中朝向完全交给里程计/陀螺仪。

各校正器一览：

| 节点 | 所需特征 | 几何/匹配方法 | 行号 |
|---|---|---|---|
| `SelfLocate`(trust) | 任意地标 | 粒子滤波，θ 锁 ±1° | 1866 |
| `SelfLocate1M` | 最近的 1 个**已识别**地标 | 直接用其地图坐标算 dx,dy；排除易混的球门区 L 角(`LOLG/LORG/LSLG/LSRG`)；要求在画面中心且不太远 | 2360 |
| `SelfLocate1P` | 1 个罚球点 | 按距离判别敌/我罚球点 → dx,dy；要求 bbox 居中 | 2260 |
| `SelfLocate2X` | 2 个 X（中圈与中线交点） | 校验 x 近似相等、y 间距≈中圈直径 → 取中点 dx,dy | 2470 |
| `SelfLocate2T` | 2 个 T（禁区/球门区边） | 校验 x 相近、y 间距≈(禁区宽-球门区宽)/2 → 四象限匹配 dx,dy | 2568 |
| `SelfLocateLT` | 1 T + 1 L（球门区角） | 校验 y 相近、x 间距≈球门区长 → 匹配 dx,dy | 2685 |
| `SelfLocatePT` | 罚球点 + T | 类似组合匹配 | 2804 |
| `SelfLocateBorder` | 边线/球门线/中线 | 取置信度最高线，用**垂距**反推 dx 或 dy（边线定 y、球门线/中线定 x） | 2920 |
| `SelfLocateLine` | 多条场线 | 类 ICP：观测线与 17 条标准线按平均距离+夹角(<0.2rad)匹配，竖线纠 y/横线纠 x，最多取两条不同向线 | 3119 |
| `SelfLocateLocal` | 单罚球点 / 双 X | `_singlePenalty`+`_doubleX` 两种局部特征，逻辑同上 | 2094 |

`SelfLocateLocal::tick`（`brain_tree.cpp:2247`）顺序尝试 `_singlePenalty` → `_doubleX`，命中即返回。

## 7. 触发逻辑：与比赛状态机的耦合

`game.xml` 的 `MainTree` 按 `control_state`（手柄 LT+X/A/B = 1/2/3）与 GameController 状态分发：

```text
control_state==2 (人工 pickup 重定位): CamScanField(未校准时) → SelfLocateEnterField
control_state==3 (自动比赛, !go_manual):
  ├─ AutoGetUpAndLocate (摔倒检测起身)
  ├─ gc_is_under_penalty:        CamScanField → SelfLocateEnterField   (重置 odom_calibrated)
  └─ !penalty:
       ├─ INITIAL:  CamScanField(未校准) → SelfLocateEnterField
       ├─ READY:    走到起始位 → 〔Locate 子树〕
       ├─ SET:      站定        → 〔Locate 子树〕
       ├─ PLAY:     → StrikerPlay / GoalKeeperPlay
       └─ FREE_KICK:各子状态下 ball_location_known 时 → 〔Locate 子树〕
```

**`Locate` 子树（`subtree_locate.xml`）= 校正器级联**，按顺序每 tick 全部执行（各节点恒返回 SUCCESS、互不阻塞，谁有特征谁纠偏）：

```text
SelfLocate(trust_direction) → 1M → 2T → PT → LT → 2X → Border   (SelfLocateLine 被注释停用)
```

**比赛进行中（PLAY）的定位**藏在 `subtree_striker_play.xml` 顶部（`:7`、`:8`）：

```xml
<SelfLocate mode="trust_direction" />
<SubTree ID="Locate" _while="decision!='find'" />   <!-- 找球时暂停定位，避免冲突 -->
```

即射手在非“找球”决策下持续运行整套校正级联；守门员侧同理在其子树中处理。

> 小结：**全局定位（含朝向）只在入场/SET/READY/罚球/起身等“非对抗”时刻发生；激烈对抗的 PLAY 阶段只做小窗平移微调**，以保证位姿连续、避免跳变干扰运动控制。

## 9. 设计特点与优势

1. **分层稳健**：高频里程计保证连续性，低频视觉校正消除漂移；典型且成熟的 map→odom 架构。
2. **多策略冗余**：从全局粒子滤波到 7+ 种几何/场线校正器，地标稀疏或某类特征缺失时仍有替代路径。
3. **强误检防护**：每次纠偏都用“全部地标残差”做一致性校验（`residual ≤ 0.4`），并对距离过远/不在画面中心/纠偏量过大（`maxDrift`）层层设限，显著降低误识别地标导致的错误重定位。
4. **场景自适应**：按比赛状态切换约束盒（入场宽搜、比赛窄搜），静止时放宽 `maxDist`，时间越久允许漂移窗越大（`trust_direction`）。
5. **朝向稳定优先**：比赛中冻结朝向解算，避免对抗中位姿抖动影响踢/带球控制。

## 10. 潜在问题与风险

> 以下含**疑似代码缺陷**（静态阅读所得，建议复核/测试验证），以及结构性局限。

### 10.1 疑似缺陷（建议优先复核）

1. **`SelfLocate2X` 与 `_doubleX` 的 y 中点计算用错变量**
   - `brain_tree.cpp:2525`：`double dy = - (p1.posToField.y + p1.posToField.y) / 2.0;` —— 两次用 `p1`，应为 `(p0 + p1)`。
   - `brain_tree.cpp:2200`：`double yc = (p1.posToField.y + p1.posToField.y) / 2.0;` —— 同样问题。
   - 影响：双 X 定位的 y 方向纠偏量偏差。虽有残差校验兜底（可能被拒），但会降低该策略成功率/精度。

2. **`SelfLocateLT` 内层循环起点疑似有误**
   - `brain_tree.cpp:2715`：遍历 `lMarkers` 却用 `for (int j = i + 1; ...)`（`i` 是 T 的下标）。T 与 L 是不同数组，应从 `j = 0` 开始，否则会漏配部分 L 点。

3. **`getMarkersForLocator` 中 `markerType` 可能未初始化**
   - `brain_data.cpp:33`：若 `label` 不属于 4 种已知类型，`markerType` 未赋值即被 push。上游虽已过滤，但缺省分支不够健壮。

### 10.2 结构性局限

4. **比赛中朝向不可纠**：PLAY 阶段所有校正器只动 `(dx, dy)`，朝向完全依赖里程计/陀螺仪。一旦摔倒/打滑/长时间累积导致陀螺漂移，θ 误差只能等到下次入场/SET/起身的全局定位才修复——而几何平移校正在错误朝向下会把误差“锁”在错误方向上。建议引入对抗中可用的朝向校正（如双地标连线方向、球门朝向）。

5. **强依赖固定 `z=0` 地面投影**：地标机器人系坐标来自 `position_projection`，当机器人躯干俯仰/地标较远时，平面假设误差直接转化为测距误差，进而污染定位。`docs/ground_plane_plan/` 的动态地面平面拟合正是为此而设，但**默认关闭**，尚未对 brain 生效——建议按其测试指南推进启用。

6. **两套地标地图需手工保持一致**：`Locator::calcFieldMarkers` 与 `BrainConfig::calcMapMarkings` 各自独立生成理论坐标，存在不一致风险，建议统一来源。

7. **`numParticles=200` 固定**：全局重定位（`enter_field`/全场 `face_forward`）在大场地、宽约束盒下，200 粒子均匀初始化可能不足以稳定覆盖，存在偶发不收敛（code=3）；可考虑随约束盒体积自适应粒子数。

8. **`SelfLocateLine` 已实现但停用**：`subtree_locate.xml` 与 striker 子树中均被注释。场线信息丰富，建议在验证稳定后纳入级联以增强少地标场景。

## 11. 改进建议（按性价比排序）

1. **修复 §10.1 的三处疑似缺陷**（低成本、直接收益）。
2. **引入比赛中朝向校正**：利用 2T/2X/LT 等已匹配的双地标连线方向或边线方向，给出 `θ` 的小窗修正，缓解 §10.4 的朝向锁死风险。
3. **推进动态地面平面投影**（`ground_plane`）从默认关闭到灰度启用，按 `docs/ground_plane_test_guide/testing_and_usage.md` 验证后接入，提升远距/俯仰下的测距精度。
4. **粒子数自适应** 与 **统一地标地图来源**。
5. **重新评估并启用 `SelfLocateLine`**，扩充少地标半场的定位能力。

## 12. 本次优化实现：基于 B-Human 复合特征的全位姿校正（`SelfLocateCircle`）

> 参考文档：[B-Human Self-Localization](https://docs.b-human.de/master/modeling/self-localization/)。

### 12.1 B-Human 的核心思路

B-Human 的自定位为 **粒子滤波（假设管理/重置）+ 每个假设一个 UKF** 的混合架构，粒子数极少（约 12）。要从“丢失定位”中恢复，依赖 **sensor resetting**——用近期观测注入新粒子。其关键在于 **complex field features（复合场地特征）**：把多个基础元素组合（**中圈 + 中线**、**罚球点 + 禁区线**）后可**直接解算出全局位姿**，从而“一次性同时降低两个平移维度与朝向的误差”，而不是当作相对地标。由 `AlternativeRobotPoseProvider` 产出 `AlternativeRobotPoseHypothesis`，并需额外过滤误检（false positive）。

### 12.2 与本仓库的契合点

本报告 §10.4 指出当前最大短板：**比赛中朝向 `θ` 不可纠**（所有几何校正器仅平移）。B-Human 的复合特征思路恰好解决它——而本仓库视觉**已检测中圈与中线的两个交点（两个 `XCross`）**，这两点既给出场地中心（x,y），其**连线方向**又给出中线方向（θ），足以解算完整位姿。

### 12.3 实现：两个全位姿校正节点（`SelfLocateCircle` / `SelfLocatePenalty`）

新增两个行为树节点（声明 `brain_tree.h`，实现于 `brain_tree.cpp`，注册 `REGISTER_BUILDER`），分别对应 B-Human 的两类复合特征。共同点：**一次性解算含朝向 `θ` 的完整全局位姿**，并复用 `locator->residual` 对【全部地标】做一致性校验（对应 B-Human 的 false-positive 过滤），通过则 `calibrateOdom(x, y, θ)` ——**含朝向**地重置 odom→field。两者均受 `max_theta_drift`（默认 0.6 rad，亦确保 π 级翻转必被拒）与 `max_drift` 门限保护。

**(a) `SelfLocateCircle` —— 中圈 + 中线**（对应 B-Human "center circle with center line"）：
1. 取 2 个 `XCross`（中圈与中线的两个交点），几何自检（间距 ≈ 中圈直径）。
2. 机器人系下：两点中点 → 场地中心 (x,y)；连线方向 `β` → 朝向候选 `θ = ±π/2 − β`（相差 π）。
3. 解 180° 二义性：取与当前 `robotPoseToField.theta` 最接近者；位置 `t = −R(θ)·M_robot`。

**(b) `SelfLocatePenalty` —— 罚球点 + 禁区前线**（对应 B-Human "penalty mark with penalty area line"）：
1. 取 1 个 `PenaltyPoint`（要求在画面中心、不太远）。
2. 取一条与底线平行的横线（`PenaltyArea`/`GoalLine`/`GoalArea`，地图中 `dir == Horizontal`，沿 ±y），置信度 > 0.8。
3. 由横线机器人系方向 `γ` → 朝向 `θ = ±π/2 − γ`（取近当前者）。
4. 由罚球点位置 `t = PM_field − R(θ)·PM_robot`，并按与当前估计的接近度判别敌/我罚球点。
5. 适用于贴近球门、看不到中圈的半场，与 (a) 互补。

二者接入 `subtree_locate.xml`，置于 `trust_direction` 之后、其余仅平移校正器之前。因各校正器共享 `lastSuccessfulLocalizeTime`（一个时间窗内仅一个生效，顺序即优先级），故复合特征可见时优先采用“信息更全”的全位姿校正。

同时修复 §10.1 的两处中点 `(p1+p1)/2` 笔误（`SelfLocate2X` 与 `SelfLocateLocal::_doubleX`，应为 `(p0+p1)/2`）。

### 12.4 影响、限制与后续

- **收益**：比赛中只要中圈或（罚球点+横线）进入视野（约 5 m 内），即可同时纠正 x、y 与朝向，缓解陀螺漂移/打滑导致的朝向锁死（直接消除 §10.4 的最大短板，覆盖全/半场两种场景）。
- **限制**：均依赖当前朝向先验做二义性消解，故定位为“已大致定位下的精修”，不替代入场全局定位；`max_theta_drift` 偏保守（>该值的真实大朝向误差会被拒，需 SET/入场全局定位修复）。`SelfLocatePenalty` 的朝向精度取决于横线方向检测质量（已用置信度门限 + 残差校验把关）。
- **后续**：可评估把全位姿候选做**多帧时间聚类**后再重置（更接近 B-Human `AlternativeRobotPoseProvider` 的多帧过滤），以进一步抑制偶发误检。
- **构建**：本仓库为 Linux 机器人侧 colcon 工程（当前开发机无 colcon/ROS，未能在此编译）；请在机器人/容器内执行 `colcon build --packages-select brain` 验证。
