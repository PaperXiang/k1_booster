# 变更报告: 边线/边界定位迁回 1.5 稳健版（SelfLocateLine + SelfLocateBorder）

- 日期 / 作者：2026-06-26 / 与 PaperXiang 结对
- 类型：迁移 / 修复（定位）
- 来源：用户对比 1.5 demo（`D:\booster\k1_booster`）发现 1.6 把 PT/Line 关了、Border 变激进

## 0. 判断结论（回答"1.5 的边线检测有没有问题"）
**1.5 的边线/边界检测没问题——反而是 1.6 把它们"削弱"了**：
- `SelfLocateLine`：1.5 有**置信度≥0.7 / 时效≤700ms / 长度≥0.5m** 三道输入过滤 + ICP 线匹配；**1.6 把三道过滤删了，然后整条关掉**。核心匹配逻辑两版一致。
- `SelfLocateBorder`：1.5 是**软融合版**（多候选加权平均 + 每 tick 最多纠 0.4–0.6m + 置信度/时效过滤）；**1.6 换成更糙的版本，且把 `max_drift` 从 1.0 放大到 3.5**（单次最多跳 3.5m，边界一误检就大跳）。

所以不是"1.5 有问题"，是"1.6 退化了"。按你的指示——**不严重就修改适配迁回**。

## 1. 改了什么
| 项 | 改动 | 文件 |
|---|---|---|
| `SelfLocateLine` 过滤 | **补回 1.5 的三道过滤**（confidence≥0.7 / age≤700ms / length≥0.5m），核心匹配本就与 1.5 一致 → 等于恢复 1.5 稳健版 | `brain_tree.cpp` |
| `SelfLocateLine` 启用 | **重新挂入级联**，用 1.5 保守参数 `msecs_interval=1500, max_dist=5.0, max_drift=1.0, validate=true` | `subtree_locate.xml` |
| `SelfLocateBorder` 参数 | **恢复 1.5 保守参数** `max_drift 3.5→1.0`、`max_dist 5→4`、`msecs 300→800`、显式 `validate=true` → 单次最多纠 1.0m，掐掉 3.5m 大跳风险 | `subtree_locate.xml` |

## 2. 没做（留作后续，按需）
- **`SelfLocateBorder` 算法本体**仍是 1.6 的糙版（无软融合/无每-tick 上限/无置信度过滤）。我只恢复了参数（已掐掉 3.5m 大跳这个**急性风险**），但 1.5 的**软融合**（渐进纠偏、不猛跳）没迁。
- 那是个 238 行的整函数替换，较大；急性风险已被参数封住，故先不动。**要的话我再单独迁这个软融合 Border**（一次变更+报告）。

## 3. 风险
- **`SelfLocateLine` 是本批最高风险项**：线段最易误检。已用"三道过滤 + 1500ms 低频 + drift≤1.0 + validate 残差校验"压到最保守，且这正是 1.5 跑过的配置。但仍是**由关变开的 live 改动**。
- **`SelfLocateBorder` 参数**：纯风险下降（跳得更小、降频），比现状更安全。
- 两者都在比赛常开的定位级联里、**未实机验证** → 见 §4。

## 4. 如何测试 / 回退
- 离线：`colcon build --packages-up-to brain`；起 `game.xml` 不崩。
- 仿真/回放：站到能看边线/场线处走动，看日志 `/locate/line/success`、`/locate/border/success` 是否在合理时给 success、校正量是否小而合理；WebUI `R+朝向线` 是否更贴、不乱跳。
- **一键回退**（互相独立）：
  - 线不稳 → `subtree_locate.xml` 把 `<SelfLocateLine .../>` 重新注释（回到 1.6 关闭态）。
  - 边界想回 1.6 激进值 → 改回 `max_drift="3.5"`（不建议）。

## 5. 道理
定位多一路"看场线纠位置"的能力（尤其地标稀疏的半场），1.5 本来就有且跑得稳；1.6 削弱+关闭后等于少了一路纠偏。把 1.5 的稳健过滤迁回来 + 用最保守参数重新打开，是低风险地补回这路能力。Border 的大跳是急性隐患，先用参数封住。
