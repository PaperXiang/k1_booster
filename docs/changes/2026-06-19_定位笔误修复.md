# 变更报告: 定位三类笔误修复（P1-1）

- 日期 / 作者：2026-06-19 / 与 PaperXiang 结对
- 类型：修复（定位校正器，**在比赛常开的 Locate 级联里**，非开关门控）
- 默认是否生效：是（bug 修复直接生效）
- 回退：`git checkout` 对应文件 / 反向改回。

## 1. 动机
定位是团队分工命脉（未定位 cost +100 直接退出竞争），且自评"鲁棒性极差"。源码核对发现 3 类笔误，使部分几何校正器算错或不稳。修掉是低成本、直接的精度收益。

## 2. 改了什么（文件 + 现象）
| 文件:行 | bug | 修复 |
|---|---|---|
| `brain_tree.cpp` `_doubleX`(~:2227) | `yc = (p1.y + p1.y)/2` 复制粘贴错 | → `(p0.y + p1.y)/2` |
| `brain_tree.cpp` `SelfLocate2X`(~:2552) | `dy = -(p1.y + p1.y)/2` 同错 | → `-(p0.y + p1.y)/2` |
| `brain_tree.cpp` `SelfLocateLT`(~:2747) | 内层 `j=i+1` 但遍历的是**另一个数组** `lMarkers`（`i` 是 `tMarkers` 下标）→ 漏配 L 点 | → `j=0` |
| `brain_tree.cpp` `SelfLocatePT`(~:2865) | **同类 bug**（`i`=posts，`j=i+1` 遍历 `tMarkers`）→ 漏配 T 点 | → `j=0`（计划只列了 LT，实现时发现 PT 同病，一并修） |
| `brain_data.cpp:33` `getMarkersForLocator` | `char markerType;` 未初始化, 未知 label 仍 push | 初始化 `'\0'` + 未知类型 `continue` 不入定位器 |

> 未改：`SelfLocate2X`/`2T` 在**同一个** `markers` 数组内的 `j=i+1`（`brain_tree.cpp:2628`）——那是正确的（避免自配对/重复对），保留。

## 3. 对比原先
- 双 X（中圈两交点）/双 X 局部、LT、PT 这几种校正：原先 y 中点算错 / 漏掉部分候选配对 → 成功率与精度受损（有残差校验兜底，多表现为"该校正时没校正"）。
- 修复后：y 中点正确；LT/PT 能考虑到此前被错误跳过的合法配对；未知地标不再带着未初始化值进定位器。

## 4. 风险
- 中低：这些校正器在比赛常开（`subtree_locate.xml` 级联），**非 flag 门控**。但每次纠偏都过"全地标残差 ≤ 0.4 + 几何自检"，错误配对会被拒；`j=0` 只是**新增**此前漏掉的候选，不会制造错误纠偏。
- 仍属定位路径行为变化、未实机验证 → 见验证。

## 5. 如何验证
- 离线：`colcon build --packages-select brain`；起 `game.xml` 不崩；**仿真/rosbag 回放**看定位是否更少跳变、双 X/LT/PT 触发是否变多且合理。
- WebUI：`R + 朝向线`位姿是否更贴合真值；`ms_since_localize` 是否更短（更频繁成功校正）。
- 出问题回退：单条 `git checkout` 即可。
