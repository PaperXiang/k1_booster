# 2026-06-18 至今总汇总与测试方案

> 范围：汇总 2026-06-18 起的主要代码/行为变更，以及赛前可执行的分层测试方案。
> 阅读对象：赛前调试人员、策略开发人员、需要判断是否回退某项改动的人。

## 1. 总体结论

从 2026-06-18 起，改动重点可以归为五类：

1. **运动行为**：追球提速、正式比赛 `Chase` 弧线追球、Adjust 超时逃逸。
2. **找球与头部控制**：主动找球重写、头部自由度限制。
3. **定位鲁棒性**：定位笔误修复、PT/doubleX 深层修复、中圈全位姿校正能力。
4. **协同与可观测性**：队友球共享、WebUI 验证遥测、FieldView 可视化增强。
5. **工程清理与安全性**：拦截解算分包、守门员不可达扑救挂载清理、死代码标注、外部资料调研。

最需要实机关注的是：

- **运动风险**：追球/找球/Adjust 会直接改变机器人移动路径，可能导致摔倒、过冲、绕球不到位。
- **定位风险**：定位修复可能提高命中率，但也必须观察是否出现异常跳变。
- **启动风险**：0618 已处理未实现 BT 节点导致 `game.xml` 崩溃的问题，后续仍需把“起树不崩”作为第一检查项。

## 3. 关键改动总览

### 3.1 运动行为

#### 追球提速与弧线追球

- **0618**：提高全局移动限速与 `SimpleChase` 速度，调试树追球从“偏角大就原地转”改为“边走边转”。
- **0619**：发现正式比赛用的是 `Chase` 而非 `SimpleChase`，因此把弧线追球补进正式比赛 `Chase`，并用 `arc_walk` 端口门控。
- **收益**：侧前方球位时更快逼近，减少“先转正再走”的时间浪费。
- **主要风险**：近球控制、绕球角度、摔倒、过冲、定位漂移。
- **回退思路**：正式比赛弧线追球可将 XML 中 `arc_walk="true"` 改回 `false`；全局限速问题需回收 config 中速度上限。

#### Adjust 绕球超时优化

- **改动**：引入绕球卡死后的超时回 chase 机制，默认关闭。
- **收益**：避免机器人长时间卡在 adjust 状态。
- **主要风险**：开启后可能在尚可调整时过早退出 adjust。
- **回退思路**：保持默认关闭或关闭对应配置。

### 3.2 找球与头部控制

#### 主动找球重写

- **改动**：头部 Lissajous 扫描与身体找球并行，找球不再是头身交替的串行等待流程。
- **收益**：更快覆盖身后/侧后区域，发现球后更快进入追球。
- **主要风险**：边转边前进时出界、撞人，或头部扫描覆盖不足。

#### 头部自由度限制

- **改动**：按官方 DOF 收口 yaw/pitch 软件限位。
- **收益**：减少越界动作和无效扫描。
- **主要风险**：限位过紧会降低侧后方找球覆盖。

### 3.3 定位鲁棒性

#### 定位笔误修复

- **改动**：修复 `_doubleX`、`SelfLocate2X` y 中点错误；修复 LT/PT 跨数组配对漏配；过滤未知地标类型。
- **收益**：提高几何校正候选完整性和计算正确性。
- **主要风险**：新增候选可能让定位校正触发频率变化，需要看是否有跳变。

#### PT 与 doubleX 深层修复

- **改动**：修复 `SelfLocatePT` 几何判据以及 `_doubleX` 方向/地图坐标相关问题。
- **收益**：让此前几乎不可命中的校正逻辑恢复可用。
- **主要风险**：命中后会实际修正位姿，必须验证残差和真值一致性。

#### 中圈全位姿校正

- **改动**：实现基于中圈+中线交点的 `SelfLocateCircle` 能力，默认不挂入正式级联。
- **收益**：有机会补足比赛中“只纠平移、不纠朝向”的结构性短板。
- **主要风险**：错误匹配会造成全位姿跳变；必须先日志/回放验证再灰度。

### 3.4 协同与可观测性

#### 队友球共享

- **改动**：新增 `k1_teammate_ball` 独立包，按置信度采信队友球，默认关闭。
- **收益**：遮球时可以借可信队友球位继续决策。
- **主要风险**：阈值配置不合适会导致过度采信或完全不采信。

#### WebUI 与 FieldView 可视化

- **改动**：增加队友球共享、找球状态、球速矢量、共享来源连线等可视化。
- **收益**：让赛场调参不再只靠日志猜状态。
- **主要风险**：显示坐标或字段含义错误会误导调试。

### 3.5 工程清理与安全性

- **拦截解算分包**：将纯逻辑和单测从 brain 中拆出，当前不影响运行。
- **守门员扑救挂载清理**：删除不可达挂载，避免误判功能已生效。
- **死代码标注**：标出不可达分支，降低后续误改风险。
- **外部资料调研**：沉淀可借鉴方案，但不直接改变运行。

## 4. 分层测试方案

### 4.1 第 0 层：构建与起树

目标：先挡住最致命的“代码没编过 / 行为树起不来”。

1. `colcon build --packages-select brain k1_teammate_ball`
2. 如拦截包纳入构建，再单独构建/测试 `k1_ball_intercept`。
3. 启动正式树：`ros2 launch brain launch.py tree:=game.xml`
4. 观察是否有：未知 BT 节点、未知端口、参数缺失、XML 加载异常。

通过标准：`game.xml` 稳定启动，无异常退出。

### 4.2 第 1 层：单机运动行为

目标：确认追球、找球、Adjust 不会带来明显运动事故。

1. **追球**：球放正前、侧前 30-60 度、近距离、远距离各测一轮。
2. **找球**：球放身后、侧后、短暂遮挡后出现，确认能扫到并退出找球。
3. **Adjust**：构造绕球不到位场景，确认不会长时间卡死；若启用超时，确认能回 chase。
4. **稳定性**：记录摔倒、过冲、绕球蹭球、起脚角度不对等现象。

通过标准：不摔、不长时间卡状态、能从找球回追球、近球不明显冲过。

### 4.3 第 2 层：定位验证

目标：确认定位修复是收益而不是跳变源。

1. WebUI 观察机器人位置、朝向线是否贴近真实场地位置。
2. 回放/仿真中观察 `ms_since_localize` 是否下降、定位成功频率是否提高。
3. 重点看 LT/PT/doubleX 命中时残差是否合理。
4. 中圈全位姿校正只做日志/回放验证，未通过前不要挂正式级联。

通过标准：定位更稳或至少不劣化；无明显突跳；朝向不出现大幅错误修正。

### 4.4 第 3 层：协同与可视化

目标：确认队友球共享和调试界面反映真实状态。

1. 两台机器人：A 看球、B 遮球，开启通信但先保持队友球共享默认关闭，确认原行为不变。
2. 开启 `teammate_ball_share.enable:true`，观察 B 是否只采信高置信度队友球。
3. WebUI 检查共享状态、找球状态、Prediction 卡片。
4. FieldView 检查本机位置、球速矢量、共享来源连线。

通过标准：默认关闭无行为变化；开启后共享来源可信；可视化与现场一致。

### 4.5 第 4 层：小规模对抗

目标：在接近真实比赛压力下观察综合效果。

1. 先 1v0：追球、找球、定位、起脚闭环。
2. 再 1v1：观察对手干扰下追球和定位稳定性。
3. 再多人：观察通信共享、角色切换、FieldView 可视化是否仍可信。

通过标准：无启动崩溃、无连续卡状态、无明显定位跳变导致的错误跑位。

## 5. 赛前 go/no-go 清单

| 检查项 | Go 标准 | No-Go / 回退建议 |
|---|---|---|
| 构建与起树 | `brain` 构建成功，`game.xml` 起树稳定 | 先修构建/BT；不得上场 |
| 追球 | 侧前方球位能斜线逼近，近球不明显过冲 | 关闭 `arc_walk` 或回收速度 |
| 找球 | 身后/侧后球能被扫到，发现后能退出找球 | 检查头部限位、扫描幅度、找球 XML |
| Adjust | 不长时间绕球卡死 | 保持超时开关关闭或调大超时 |
| 定位 | 位姿不突跳，校正频率合理 | 回退对应定位修复或不要挂新校正 |
| 队友球共享 | 默认关闭无变化；开启后只采信可靠队友球 | 关闭 `teammate_ball_share.enable` |
| WebUI/FieldView | 显示与现场一致 | 不用其做决策依据，先修显示 |

---

## 6. 推荐测试顺序

1. 构建 + `game.xml` 起树。
2. 单机追球和找球。
3. Adjust 卡死恢复。
4. 定位回放/WebUI 验证。
5. 队友球共享和可视化。
6. 1v0、1v1、多人小场景递进测试。

不要跳过第 0 层和第 1 层；这两层不过，后面的协同和对抗测试结论都不可靠。
