# 修复 3v3 比赛策略现实性问题

## Goal

在保留现有 UDP 通信机制、保留用户当前 3v3 本地配置的前提下，修复提交 `3bff8bbd32d4285a81ef352c50a393c47e2c5e41` 中会直接影响真实 3v3 比赛稳定性的策略问题，使角色交接、阵型、任意球和首触球保护具备明确降级路径与可验证行为。

## Requirements

- 守门员交接必须在接任者确认后才允许原守门员退出；未确认、目标离线或超时必须安全回滚，且全队可通过周期状态最终收敛。
- 3v3 阵型默认使用仅依赖共同输入的确定性 ID 映射，不以各机不同步的队友位姿作为默认分配依据；保留按距离分配作为显式实验选项。
- 阵型目标必须同时满足场内边距、守门员专属禁区、对方开球半场/中圈和任意球距球约束；修正一项约束不得破坏先前约束。
- `freekick_attack` 与 `freekick_defense` 必须接入正式任意球行为树，并在阵型关闭或规划失败时回退现有 `GoToFreekickPosition` 流程。
- kickoff guard 不得因单帧 field 坐标跳变直接解除；需要连续可信观测，并在明显定位跳变时重新建立或延后确认基准。
- 保留用户对 `src/brain/config/config.yaml` 中 team/player/3v3 的未提交调整，不覆盖这些值。
- 不处理 robot-to-robot unicast 的赛事合规问题，也不重写通信传输层。
- 为适合自动验证的纯算法和状态边界补充针对性测试；无法自动验证的实机时序明确记录验证方法。

## Acceptance Criteria

- [ ] 交接包丢失或目标未确认时原 GK 保持职责，超时后不会留下无人守门状态。
- [ ] 3v3 默认配置下两名 field players 对 kickoff/freekick 槽位使用确定性映射。
- [ ] 边线、角落和禁区附近生成的阵型目标满足全部适用几何约束，且有自动测试覆盖。
- [ ] formation 开启时任意球正式进入对应 planner；关闭或无有效计划时行为与旧流程兼容。
- [ ] 静止球伴随单帧定位跳变不会解除 kickoff guard；真实连续球移动仍可解除。
- [ ] 相关包可构建，新增测试通过，改动文件无新增 lint/编译诊断。
- [ ] 最终报告列出仍需多机或实机验证的残余风险。

## Constraints

- 实际比赛规模为 3v3。
- 不修改或还原用户当前未提交的 `team_id`、`player_id`、`number_of_players`。
- 不创建提交、不推送，除非用户后续明确要求。
