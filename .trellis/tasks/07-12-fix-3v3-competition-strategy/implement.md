# 实施计划

## 实现步骤

- [ ] 深读角色交接、特殊比赛状态、任意球子树及 brain 构建测试结构。
- [ ] 将 GK 交接调整为“请求期间原 GK 保持、观察周期角色确认后提交、超时回滚”。
- [ ] 把 3v3 默认阵型映射切换为确定性 ID 分配，同时保留实验性按距离选项。
- [ ] 重构槽位合法化为可验证的联合约束，并让无合法解返回失败。
- [ ] 将任意球 formation 分支接入正式 striker freekick 子树并保留旧节点回退。
- [ ] 为 kickoff guard 增加连续观测确认与定位跳变抑制。
- [ ] 增加聚焦的纯逻辑/几何测试，并注册到 brain 构建。
- [ ] 运行格式检查、构建、测试和 linter；复核用户本地配置差异未被覆盖。

## 验证重点

- 3v3 两名前锋在共同 ID 集合下得到唯一且一致的槽位。
- 球位于边线、角落、禁区附近时，目标不出界、不进限制区且保持规定距离。
- GK 交接请求丢失或未确认时，原 GK 不提前退出。
- 任意球 formation 开关关闭时仍使用原流程；开启但规划失败时安全回退。
- 单帧定位跳变不解除 guard，连续真实球移动能够解除。

## 风险与回滚点

- 不改变通信传输和消息结构，降低多版本机器人互操作风险。
- 行为树改动保持旧节点作为 fallback。
- 用户当前 `config.yaml` 的 team/player/人数差异属于受保护改动，仅修改本任务新增或明确要求的策略字段。
