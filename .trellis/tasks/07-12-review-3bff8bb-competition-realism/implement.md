# 审查执行计划

## 步骤

- [ ] 获取目标提交元数据、父提交、完整 diff 和变更文件清单。
- [ ] 快速建立仓库包、节点、启动、配置、消息和比赛文档结构图。
- [ ] 逐个深读目标提交变更文件，并追踪高风险的直接调用方、依赖方和接口定义。
- [ ] 对照提交前版本，验证行为变化是否有明确需求与保护机制。
- [ ] 按真实比赛场景检查规则、硬件、时序、通信、坐标、单位、故障恢复和安全边界。
- [ ] 审查现有测试，执行不改动工作树的相关静态检查或测试（若环境具备）。
- [ ] 复核所有严重/警告发现，排除被代码或配置证伪的误报。
- [ ] 输出问题优先的最终报告、总体结论和分层验证建议。

## 验证命令候选

- `git status --short --branch`
- `git show --stat --summary 3bff8bbd32d4285a81ef352c50a393c47e2c5e41`
- `git diff <parent> 3bff8bbd32d4285a81ef352c50a393c47e2c5e41 -- <relevant paths>`
- 与受影响包一致的构建、测试或静态检查命令；仅在阅读包说明后确定。

## 风险与停止条件

- 若目标提交不在当前仓库历史中，先确认是否需要获取远端对象，不猜测内容。
- 若比赛组别、规则版本或硬件型号影响结论且仓库无证据，记录为阻塞性外部假设并向用户询问。
- 不执行会修改产品代码、重置工作树、切换分支或产生提交的命令。
